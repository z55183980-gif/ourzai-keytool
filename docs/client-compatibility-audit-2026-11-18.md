# Claude / Codex 启动、检测与密钥写入审计

## 修复后的复测（2026-11-18）

- 以下审计基线保留用于对照。修复后，Windows 三组真实 CLI 在临时用户目录、假密钥和本地端点下通过九个用例。其中 Codex 0.100.0 的自动选择已命中本地 Responses，未尝试连接官方推理域名；0.167.0 和 0.169.0 保留内置写法的覆盖。三个 Claude CLI 均收到正确的 Messages 请求。发布工作流已加入锁定版本的回环测试，不向该测试任务提供签名密钥。
- 兼容选项现在能强制独立 provider。Codex CLI 不低于 0.167.0（首个实测通过版本）才沿用内置写法，更低或无法识别的版本写入时选择独立 provider。启动本工具里的某把密钥、而现有配置是该版本未验证的内置网关写法时，启动预检会要求先重新保存，不会自动改用户文件；沿用当前配置和切回官方不受此限。桌面端不借用 CLI 版本来证明兼容性。
- Codex 在配置目录内记录接管过的模型字段及凭据指纹（不是密钥原文），随配置事务备份、还原。无归属记录的历史网关密钥，只有与本工具保存的某把密钥相同时才在切回官方时移除，否则拒绝切换、不直接切到官方端点；归属记录损坏时按无记录处理并重建。旧版曾明确覆盖的官方登录仍须从原备份恢复；新代码不能事后重建凭据。
- Claude 桌面版密文只在配置条目、网关地址和模型都与本工具上次写入一致、且该密钥未被替换时才绑定到那把密钥，绑定后密文一变即不再认；旧记录缺这些信息时不认，重新保存一次即可。写入后、首次扫描前若在桌面版内换成同地址同模型的另一把密钥，仍可能误认。桌面与 CLI 独立校验；仅别名变化也会写入；格式错误的 env 拒绝常规写入，体检提供“备份并修复”（仅 Claude Code CLI，只替换 env）。配置读取失败显示为“未能识别”，不再当作文件损坏锁死启动。项目文件存在时提醒核对最终服务，未尝试推断组织策略或验证付费服务。
- 四个桌面/CLI 入口的本机预检与真实桌面推理是不同验收项。macOS、历史桌面版本和生产登录仍须在测试账号上单独验证。

2026-11-18（新加坡时间），Windows x64，KeyTool 0.2.8，基线 `11e7cdb`，含已有的前端工作区修改。仅审计，未修改产品逻辑或用户配置。

## 实测范围

项目的生产配置生成函数 + 临时用户目录 + 假密钥 + 本地 HTTP 服务。通过要求：实际 CLI 请求命中正确路径、认证及模型符合预期、返回流式文本并正常退出。不是付费生产请求，也没有用桌面端测试账号完成登录。该测试不经过 GUI 保存入口和系统凭据库。

| Windows 目标 | 结果 |
| --- | --- |
| Codex CLI 0.100.0 | 内置 OpenAI provider + 顶层 `openai_base_url` + `auth.json` 失败。CLI 明确报告重试 `https://api.openai.com/v1/responses`，测试代理已拦截，本地 Responses 没收到请求。同一模型、密钥和 CLI 换成独立 provider + bearer 成功。 |
| Codex CLI 0.167.0、0.169.0 | 两个版本均实测上述两种写法通过。本机终端 PATH 是 0.167.0，KeyTool 实际指定的可执行文件是 0.169.0。 |
| Claude Code 2.1.20、2.1.322、2.1.326 | 三个版本均用 `settings.json` 的 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_AUTH_TOKEN` 成功请求 `/v1/messages`。测试只启用用户级设置。 |
| Claude Desktop 5.11492.5.0、Codex Desktop 26.1111.2228.0 | Windows 安装发现、版本读取、启动命令预检通过；没有启动真实桌面会话、验证配置热加载或实际推理。 |

本机 Codex 配置（脱敏核对）使用内置 `openai`、顶层第三方 `openai_base_url` 和 `auth.json` 中的 `apikey`；未选择额外 profile，未指定凭据存储，检查的进程级 OpenAI/Codex 地址和密钥覆盖变量未设置。还有应保留的插件、marketplace 配置。**建议保留这种已在新 CLI 实测成功的写法，不全量迁移用户配置。** 没有测试本机真实 key 或真实网关，项目文档不记录其地址、密钥或认证文件内容。

KeyTool 的版本查询当次返回 Claude CLI 2.1.326、Codex CLI 0.169.0、两个桌面版与上表相同。未升级现有安装。前端 57 项通过且生产构建成功；Rust 单元测试 155 项通过、3 项忽略，集成测试 3 项通过。旧 CLI 的真实失败不在常规单元测试覆盖内。不能从两个通过版本和一个失败版本推断精确版本分界。

## 问题与建议

第一项有真实客户端复现。其余问题根据现有代码控制流确认，影响依赖所列条件，不代表用户已经发生凭据丢失或运行错误。

| 优先级 | 触发条件和影响 | 修复及回归断言 |
| --- | --- | --- |
| P1：旧 Codex 路由、无效兼容开关 | `src-tauri/src/commands.rs:782` 只按认证文件/存储选写法，不按目标版本。`conservative` 虽由高级界面传入，后端不读取，启动页还固定传 false。版本预检能运行 `--version`，配置回读能读出网关，两者都不能证明推理目的地正确。 | 已验证版本保留本机写法；对已验证不兼容的 CLI 使用测试通过的独立 provider，不改官方凭据；未知版本不静默猜测或退回官方端点。正确联通兼容选项。单测之外按目的地主机和 API 路径验收。 |
| P1：切回官方可能误删用户凭据 | `src-tauri/src/commands.rs:936` 只要 `auth.json` 为 `ApiKeyOnly` 就删除其 key。如果独立 provider 生效，该文件另存用户自己的官方 API key，也会被删除。`src-tauri/src/codex_config.rs:142` 则保留网关的模型和推理强度；网关专用模型在官方服务未必可用。 | 记录哪些字段由本工具接管及其旧值；只恢复仍属于本次写入的字段。覆盖独立 provider + 原有官方 API key、切换后外部修改、网关专用模型。 |
| P1：外部修改可能被旧快照覆盖 | `src-tauri/src/commands.rs:704` 读旧内容作合并，`:807` 加入事务；`src-tauri/src/atomic.rs:128` 入事务时重读并据此检查冲突。若客户端在两次读取之间保存，新内容会被当成基线，仍可能提交基于旧内容的合并结果。Claude settings 和 Codex auth 使用同一模式。 | 将合并时读取的原始快照传给事务；不匹配即停止并要求重读。回归覆盖入事务前、入事务后两种并发修改。 |
| P1：Claude Desktop 可能认错加密密钥 | `src-tauri/src/state.rs:141` 首次遇到密文就绑定到上次写入的 profile；若写 A 后、首次扫描前换成同地址的 B，就可能将 B 显示为 A。`src-tauri/src/claude_desktop.rs:141` 仅识别 v1 密文前缀，未来新格式可能被当作普通字符串。 | 区分“上次写入”与“已验证”；未知密文版本不允许按明文收录。测试同地址换 key、切配置条目、密文格式升级。 |
| P2：用户级检测不等于项目实际生效 | `src/launchFlow.ts:59` 的扫描不带工作目录；项目设置、托管策略不在此扫描内。`:66` 的提前返回只核对 Claude 的密钥 profile 与主模型，别名变更可以跳过写入。 | 分开显示用户级匹配与项目内有效配置；不能确定时明确提示。将本工具管理的别名纳入比对，不覆盖项目或组织策略。 |
| P2：Claude 写入与扫描校验不一致 | `src-tauri/src/claude_config.rs:50` 只检查顶层对象；`:78` 碰到非对象 `env` 会用空对象重建，`src-tauri/src/detect.rs:526` 却判作损坏。直接配置入口可覆盖异常节点。 | 合并、回读、修复共用同一结构校验；非对象 `env` 只允许显式备份修复。 |
| P2：Claude 检测失败未隔离 | `src-tauri/src/detect.rs:89` 即使只为 CLI 保存，也同时扫描桌面端；一方读取错误会使整份扫描失败，反向亦然。 | 按 CLI/Desktop 分目标读取和返回错误，回归分别锁住两个目录。 |
| P2：启动预检不核对 CLI 身份 | Windows 自定义路径在 `src-tauri/src/launcher.rs:313` 主要检查扩展名；`src-tauri/src/client_setup.rs:114` 同时接受两个产品的版本标记和纯版本号。选错 CLI 也可能通过，最后写的是一家的配置，启动的是另一家。 | 检测携带预期产品；明确是另一产品就拒绝。对只返回数字的旧包装器提示身份未确认。 |

## 发布门禁与边界

1. Windows CLI 将上表的旧版、已安装版和候选稳定版加入自动回环测试。覆盖空配置、已有官方登录、系统凭据库策略、切回官方、备份恢复和工作目录覆盖。不要为了探测路由用用户真实密钥试发请求。
2. 两个桌面端分别验收冷启动、运行中切换后完整退出、升级前后配置迁移和组织托管。至少在 Windows 与 macOS 用测试账号验证。预检或配置文件写入成功不应展示为登录/推理已验证。ARM64、WSL、macOS 和历史桌面版均不在本次实机范围。
3. 第三方 Claude 服务未做推理连通性探测（`src-tauri/src/commands.rs:1220`），应明确标示。模型目录可读不等同于模型和密钥可用于 Messages/Responses。

复核命令：`npm test`、`npm run build`、`cargo test --locked --manifest-path src-tauri/Cargo.toml --lib --tests`。启动预检及版本查询分别使用 `launch_preflight` 和 `client_versions` 两个 Cargo 示例。回环测试：`python scripts/real-client-e2e.py --claude <指定版本的程序> --codex <指定版本的程序>`；不要替换用户在用的可执行文件。
